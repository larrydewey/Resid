# Plan: Knowledge Graph as the Sole IR (spec v3.5 §3)

Status: ACTIVE. Written 2026-09-26.

## Why

The spec (§3) has always described programs as a knowledge graph, and a
debugger was meant to walk that graph. The Rust stage-1 `resid-ir` had the
right node shape (`bootstrap/rust-stage0/crates/resid-ir/src/graph.rs:299`),
but only an optional `--graph-reduce` path used it. The self-hosted port
measured parity on output bytes alone, so the graph was never ported, and
Phase D archived it. Today typecheck, codegen and reduce all work on source
text. The root cause is that §3 had no observable contract. v3.5 adds one:
node schema, edges, derivations, facts, and a graph artifact.

## Locked decisions

- The graph is the sole IR between parsing and lowering. No pass re-reads
  source text.
- Debugger scope is static and live. Static means walking the artifact after
  the build. Live means mapping PC and runtime values to node ids.
- The node model is Rust `resid-ir`'s `Node` plus typed edges (operand, def,
  seq, derive, lowered), reasons, and facts (§3.2a).
- Spec first (done in v3.5), then build.
- Existing constraints still hold: no GC or refcounting, a self-compile fixed
  point at every commit, and `ulimit -v` on self-compiles.

## Migration strategy

Build the graph pipeline next to the text pipeline behind `--graph`. Test it
differentially against the text pipeline on the conformance suite, the reduce
suite and the self-compile. Then make it the default and delete the text
passes. `driver.resid` stays generated by `merge_driver.py`, and new modules
are imported the same way `reduce.resid` is.

## Phases

- [ ] G1 Graph core: `examples/graph.resid`.
  - Nodes stored as struct-of-arrays with id = index: kind, type, knowledge,
    and dep offsets into one shared dep list.
  - Hash-consing for pure nodes, content hashes, and the CBOR writer
    (§34 schema).
  - Parser from tokens to graph, with spans. It replaces body slicing.
  - Memory budget: stay within about 1.5x of today's 283MB self-compile peak.
    Use phase-scoped arenas.
- [ ] G2 Resolution and type checking on the graph.
  - def edges, types on nodes, and capability and effect sets.
  - Port `typecheck.resid` checks by walking nodes instead of text.
  - Exit criterion: identical diagnostics on `tests/conformance`.
- [ ] G3 Reduction on the graph.
  - Port fold, beta, eval, specialize, generalize, dead-arm and elide from
    `reduce.resid`, recording derive edges and reasons.
  - Facts: range and nonzero first (overflow and div0 discharge), then
    length (bounds), tag (arm selection), fields and path.
  - Exit criterion: `tests/reduce` passes, and the self-compile specializes
    at least as much as today.
- [ ] G4 Lowering from the residual graph.
  - Codegen walks residual roots.
  - Every instruction gets a DILocation keyed by node id. Residual bindings
    get dbg.value with their node id.
  - The graph hash is embedded in the binary.
  - Exit criterion: `./boot.sh` reaches a fixed point with `--graph` as the
    default.
- [ ] G5 Tools and conformance.
  - Emit notes as a projection of the graph.
  - `resid why` queries by symbol, file:line or node, covering derive chains
    and reasons.
  - `resid-graph` view and DOT output.
  - A conformance checker for the §3.4 invariants and lowered coverage.
- [ ] G6 `resid debug`.
  - Static mode first: walk the graph, show knowledge, facts and derivations.
  - Live mode reads the DWARF node map. First backend: drive gdb/lldb
    (MI). The goal is a native ptrace backend with a DWARF reader, so the
    toolchain stays resid-only.
- [ ] G7 Retire the text passes.
  - Delete the text typecheck, codegen and reduce paths, the `gr_*` pass and
    the notes line-scan.
  - Update AGENTS.md and PROGRESS.md.

## Open questions

- Live debugger backend: decided. gdb/lldb first, native ptrace as the goal.
- Facts: all of §3.2a, staged in the order listed under G3.
