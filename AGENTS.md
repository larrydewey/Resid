# Resid Language

Resid = eager compile-time language: compiling mean maximal authorized reduction of first-class knowledge. This repo hold language spec plus in-progress Rust/Cargo build.

- **Source of truth**: `resid_specification.txt` — full language spec (now **v3.0 — Production Ready**). All design question must get answer from it, no exception.
- **Implementation**: Cargo workspace. Members under `crates/` (lexer, parser, ir, type, codegen, builtin, build, residc) and `tools/` (fmt, notes, cache, graph, why).
- **Status**: lexer 17, parser 88, resid-ir 46, resid-type 173, resid-codegen 129, residc 27 — **480 tests pass**. Operator precedence per spec §27 (multiplicative > additive > … > logical AND/OR; binary left-associative, ranges right-associative). `resid-ir` build spec-§6 primitive numeric types plus mixed-width widening. `resid-type` cover literal inference, widening, signed/unsigned mixing rejection, bitwise/float errors, cast, if, RT, built-in extern signatures, `Str + Str`, `check_program`, and (Step 1) lists, structs, options, pattern matching, numeric overload resolution (`IntToString`/`UIntToString`/`FloatToString`/`BoolToString`/`ToString`), numeric widening at call sites, string introspection built-ins (`str_len`/`str_char_at`/`str_from_code`/`str_slice`), wide ToString built-ins (`Int128ToString`/`UInt128ToString`/`Int256ToString`/`UInt256ToString`/`Int512ToString`/`UInt512ToString`), and literal-overflow rejection (spec §6): `infer_expr_expected` rejects a literal that doesn't fit the expected numeric range, and `lit_type`/`literal_compatible` derive widths from the literal's magnitude string so >u128 literals infer wide types. `resid-type` also reject shadowing everywhere (spec §7) via `Env::try_insert` — same-block, nested-block, for-in loop vars, pattern binds, and duplicate params all error; sibling blocks still bind freely. `resid-codegen` spit out verified LLVM IR: functions, arithmetic, casts, calls, bool, string literals/f-strings/raw strings (global constants), string-concat folding, extern built-ins (`print`/`println`), boxed composite values (`List`/`Struct`/`Option` via `resid_box_*` runtime calls, `match` with tag checks + phi joins), Bool↔i8 C ABI widening (user functions declare Bool params as i8 and narrow to i1 on entry), runtime value formatting helpers, `value?`/`value else { … }` unwrap (payload from box slot 0), nested-`if` phi joins, early `return` in if/else branches (emitted as a real `ret`, enabling recursion), and wide integer support — `Int(128)`/`UInt(128)` (i128 lowering, literals built from full decimal value via `const_int_from_string` with magnitude-derived width when no target, `Int128ToString`/`UInt128ToString` runtime decimal printers) plus `Int(256)`/`Int(512)` arithmetic via LLVM arbitrary-width integers and `Int256ToString`/`UInt256ToString`/`Int512ToString`/`UInt512ToString` limb-decomposed C-ABI helpers. Float(128) is the widest binary float (spec v3.1 — F256/F512 removed; arbitrary precision is carried by the Dec(N) decimal family, implemented): `float_type(128)` lowers to LLVM `fp128`, `f128()` converts, `Float128ToString` prints 36 significant digits with full exponent range via binary bignum, and f-string interpolation of Float(128) uses `Float128ToString` (not a lossy f64 widen). Also fixed: float-typed functions with no trailing return emit a proper fp zero (was `ret i1 false`, a module verification failure), and an `if` whose then/else both return marks the block terminated with `unreachable` in the dead merge block. **Dec(N) type system (spec v3.1 §6.6a)**: `NumericType::Dec(u16)` in resid-ir (no fixed width, `is_dec()`), `numeric_result_type` gives `Dec(N) op Dec(M) -> Dec(max(N,M))`, comparisons → Bool, mixing Dec with Int/UInt/Float → `DecMix` hard error, bitwise/shift → `DecOp` error; lexer scans `m`-suffix decimal literals (`1.5m`, `5m`) carrying digits verbatim + i32 exponent (`DecLit{digits,exp}`); type checker infers Dec(34) default, accepts `Dec`/`Dec(N)` spellings, synthesizes open-ended `dN` helpers (from Dec/Int/Str; `d4(Float)` rejected) and lets `iN`/`uN`/`fN` take Dec args. **Dec(N) runtime (done, spec §6.6a)**: `resid_dec` is a 520-byte struct `{ i8 sign, i16 nd, [512 x i8] digits, i32 exp }` and always crosses the LLVM↔C boundary as pointers (`void f(resid_dec* out, …)` for struct-producing functions, `const resid_dec*` operands, scalar returns) because clang and LLVM disagree on by-value aggregate ABI for it. Arithmetic is exact add/sub/mul plus division to N+2 guard digits, all rounded once to `prec` significant digits (half away from zero) inside `resid_dec_round`; display is fixed notation with all N significant digits, trailing zeros preserved (`Dec(4) 1.5m` → `"1.500"`). Codegen emits pointer-ABI calls via `dec_slot`/`dec_call_out`, casts via `cast_to_dec`/`cast_from_dec` (Dec round / Int via i64-or-i128 / Float via %.17g / Str parse; back to Int/UInt with runtime bounds + integrality checks, Float lossy), `dN` conversions are synthesized (no extern — intercepted in `lower_call`), and `iN`/`uN`/`fN` route Dec args through the runtime (`resid_dec_to_int`/`resid_dec_to_f64`). A `Dec main()` returns a struct by value, which LLVM lowers via a hidden sret pointer libc doesn't provide — so the user `main` is emitted as `resid_main` and a C-ABI `i32 @main()` wrapper (discarding the Dec result) is synthesized (`wrap_main`). Proven by e2e test `run_dec_exact_arithmetic` plus 7 resid-codegen IR tests. Integer literals keep their digit strings in `IntKind` (`Decimal(String)`/`Hex`/`Binary`/`Octal`), so literals beyond `u128` survive lexing and codegen builds the full-width constant from the raw digits + radix. `resid-parser` handles C-style casts `(Type)expr`, named call args, raw/byte strings, `_ = expr` discard, struct destructuring, and bare block statements; the type checker (not the parser) rejects undefined variables. Functions may be called before their definition (all declared before lowering), so forward references and mutual recursion work. **M4 done**: `examples/lexer.res` (bootstrap lexer written in Resid) reads a `.resid` file via `filesystem.read_all(RESID_LEX_SRC)` and prints the token stream — C-style comments (`//`, `/* */`), string/raw/byte/f-string/char literals, dec/hex/bin/oct ints, floats, ident/keyword, operators. Proven by e2e test `bootstrap_lexer_tokenizes_source`. **M5 done**: `examples/parser.res` (bootstrap parser written in Resid) reads a `.resid` file via `filesystem.read_all(RESID_PARSER_SRC)`, recursively descends with position threaded through a `{ pos, ast }` struct (immutable bindings), and prints one S-expression AST line per declaration — type-def product/sum, func with params/defaults, bind/discard/return/if-else/while/for-in/expr/block statements, precedence-climbing binary expr (spec §30), unary, calls, field/index/slice, list/struct literals, match, ranges, f-strings/raw/bytes/chars, provider calls. Proves itself by parsing `examples/lexer.res` cleanly to EOF. Proven by e2e test `bootstrap_parser_builds_ast`.
- **Runnable natives**: `residc <f> build [-o out]` build native binary (clang + tiny C runtime `crates/residc/resid_rt.c`), `residc <f> run` build and run it (exit code carry through), `residc <f> emit-ir` print LLVM IR. First bootstrap stage: Resid programs can print to stdout, return exit codes, and format all value types to strings.
- **Branch**: `master` (uncommitted).
