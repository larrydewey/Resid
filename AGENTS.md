## Communication
When caveman mode is active, apply wenyan-style compression: omit subjects, use verb-first order where natural in English, drop all particles/conjunctions, state cause→effect in minimal words. Output language: English.   

- **Status**: The compiler is self-hosted and cargo-free: `./boot.sh` links the committed seed (`build/boot/seed.ll`) and must reach a byte-identical self-compile fixed point. Its pipeline runs entirely on the knowledge graph (spec §3, `PLAN-graph-ir.md` G0–G7): parse (`compiler/graph.resid`), resolve (`resolve.resid`), check (`gcheck.resid`, with instantiation of generics and behaviors in `mono.resid`), reduce (`greduce.resid`), lower (`lower.resid`), and the graph artifact (`gart.resid`). The text checker, reducer, codegen and notes scan are retired. The source is read after parsing only for diagnostic text and source-map lines. `compiler/driver.resid` is generated by `tools/merge_driver.py` from `compiler/codegen.resid` (the LLVM emission layer) and `compiler/typecheck.resid` (the type algebra), followed by the hand-written driver tail. Self-hosted suites: `tests/conformance/run.sh` (401), `tests/reduce/run.sh` (19), `tests/provenance/run.sh` (62, trailer signing, trust modes, evidence against attestation, forged records under a valid signature), `tests/pkg/run.sh` (97, package integrity plus the local, remote and served registry transports, and a registry served over TLS, fetched artifact by artifact, then resolved), `tests/tls/run.sh` (135, TLS server authentication: trust store, issuer CA rules, three signature algorithms, CRL revocation, OCSP responses including delegated responders -- plus the TLS *server*: key loading, certificate/key match, pinned signatures, ClientHello parsing, and live handshakes against this repository's own client and, when installed, `openssl s_client` -- plus the TLS *client* end to end (`tests/tls/client.resid`: handshake, one request, the decrypted reply, and refusals by name and by address)), `tests/crypto/run.sh` (≈13,000: Wycheproof vectors for every primitive, RFC 6979, RFC 9180 HPKE, COSE, 31 X.509 links including AMD's real SEV ARK/ASK chains, round trips, and a mutation fuzz of every untrusted-input parser), `tests/ct/run.sh` (19, constant time under valgrind memcheck on the optimized binary, with a negative control; skipped without valgrind), `tests/runtime/run.sh` (16, including buffered stdin and `lib/readline.resid` on a pty), `tests/http/run.sh` (3: `lib/httpserv.resid` against in-process clients, whole and streamed, and `examples/http_server.resid` driven by concurrent python3 clients), `tests/lsp/run.sh` (18), `tests/regex/run.sh` (`lib/regex.resid` against Go's `regexp`, RE2, on random patterns; skipped without go), `tests/ledger/run.sh` (27, the crown example: `examples/ledger.resid` with its library and inline tests in `examples/ledger_core.resid` and its native fee schedule in `examples/ledger/fees.c`/`fees.ll` -- exact `Dec(4)` money, named behaviors, a generic `total`, a folded compile-time rule schedule, the confined native call, and a signed release verified then tampered) and `tests/graph/run.sh` (700, including resid-why, resid-graph and resid-debug, live through its own ptrace backend and, when installed, gdb). The Rust pipeline and the Rust tools (`bootstrap/rust-stage0/`, `tools/resid-lsp*`, `tools/resid-notes`, `tools/resid-cache`) are deleted and in git history; the language server is `residc lsp` (`compiler/lsp.resid`). The compiler itself takes about 1.4s at a 294MB peak on the self-compile (clang's optimization and LTO link take the rest, about 13s). No `ulimit` is needed: the runtime's allocator enforces a memory budget, 4 GB for the compiler (`resid_mem_limit_set` in `compiler/driver.resid`), overridden by `RESID_MEM_LIMIT` (MB).
- **Install**: `./install.sh` puts `residc` (wrapper setting `RESID_HOME`), `stage2.bin`, `rt.ll`, `lib/` and a signing key (`keys/`, kept across reinstalls) in `~/.resid` (`RESID_INSTALL` overrides); `./uninstall.sh` removes it (`--purge` also the key). The driver finds the standard library at `$RESID_HOME/lib` in an install, else `$RESID_HOME/../../lib`, and the signing key and keyring under `$RESID_HOME/keys` after `keys/`. An install goes stale on every reseed or runtime change: `boot.sh` refreshes an existing install after a successful build or `--bootstrap-from-self` (`RESID_NO_INSTALL_REFRESH=1` skips it); after any manual rebuild of `build/boot/`, run `./install.sh` again before testing through `~/.resid/bin/residc`.
- **Runtime internals**: `resid_arena_*`, `resid_bulk_*`, the persist copies, `resid_internals_set`, the `resid_raw_*` primitives (PROGRESS §0zh) and the `resid_fmt_*` text-formatting primitives of §14.1 are compiler-only (E0220): allowed only in files under `compiler/` or `runtime/rt/` (never `lib/`), with `--runtime-internals`, which the driver accepts only for `compiler/driver.resid` or a `runtime/rt/` entry (`boot.sh` passes it). A user program reaches the formatting only through an f-string hole's spec.
- **Resid runtime**: the whole runtime is Resid, with no C library: programs are `-static-pie -nostdlib` binaries (plus libgcc) whose `_start` (emitted with `main`) calls `resid_start` (self-relocation, TLS); memcpy/memmove/memset, setjmp/longjmp and clone are naked assembly the compiler emits into the runtime module; malloc, threads, float text, getenv/exec and DNS are in `runtime/rt/`. `runtime/rt/*.resid` is lowered by `--runtime-module` into the committed `build/boot/rt.ll` (checked by `boot.sh`, regenerated by `--bootstrap-from-self`; commit it with the seed). Runtime code may not rely on runtime features it implements; a new compiler feature used by `runtime/rt/` needs a reseed with the old source first. When a port deletes C that stage1 needs, lower `rt.ll` first with the committed compiler (`build/boot/stage2.bin runtime/rt/rt.resid --runtime-module -o build/boot/rt`), then reseed.
- **Website**: `website/` holds the documentation *content* (`src/content/docs`) and one configuration file, `book.toml`. Astro/Starlight is retired: `website/serve.sh` builds [resid-book](https://github.com/larrydewey/resid-book) (a book/docs server in Resid, on resid-datastar) from the sibling checkout and serves the same content at `book.toml`'s `base` (`/Resid`), with sidebar topics, an on-this-page list, prev/next, live Datastar search, a theme toggle and highlighted code fences. `tools/check_doc_examples.py` still compiles and runs every complete example in `src/content/docs` and is independent of the server. The Astro sources (`astro.config.mjs`, `src/styles`, `public/`) are still present but unused; delete them once resid-book is on par with Starlight.
- **Registry**: `tools/resid-pkg.resid` packs, signs, publishes, serves and
  indexes; `tools/resid-manifest.resid` resolves and verifies. A registry is
  named by `[registry] path` (a directory) or `[registry] url` (an `http://` or `https://`
  base) -- not both. `resid-pkg serve <registry> [--port N] [--port-file F]
  [--cert F --key F]` is the publish side (TLS 1.3 with the cert and key,
  both refused at startup if they disagree): loopback only, GET/HEAD (PUT only with --upload), and a request
  path that could name a file outside the registry directory is refused. It
  runs on `lib/httpserv.resid` with four worker regions (`--requests N`: one).
  `resid-pkg serve --upload <keyring> --index-key <key>` takes `PUT
  /pkg/<name>-<version>.resid-pkg` signed by a keyring key (`resid-pkg
  upload <dir> <url> <keyfile> [--ca F]`), never replaces a version, and
  re-signs the index; storage goes through the `RegStore(T)` behavior
  (`DirStore` ships). `resid-pkg index list|add|remove|verify` are the publisher's non-publish
  operations; every write re-signs the whole index, and `index add` refuses a
  hash that contradicts an archive already published under that name/version.
  `url = "https://..."` goes over TLS 1.3 (`lib/tlsclient.resid`) and needs
  `[registry] ca` (a PEM bundle or a directory of DER certs; no default, so
  no store means a refusal, never a downgrade); the server side is
  `lib/tlsserver.resid`/`lib/tlswire.resid`. `tools/resid-fetch.resid`
  mirrors one artifact. `[signing] require_signatures` is
  enforced: the signed index no longer admits a package by itself.
- **TLS server**: `lib/tlsserver.resid` (the handshake, `TLS_AES_128_GCM_SHA256` and x25519 only, an alert for every refusal) with keys from `lib/tlskey.resid` (PKCS#8 or SEC1, PEM or DER, Ed25519 or ECDSA P-256/P-384) and the transport in `lib/tlswire.resid`. `lib/httpserv.resid` declares `Wire(T)` and `Accept(T, C)` and runs its connection path over them, so one handler serves both. The key file's mode is not checked: there is no stat verb.
- **TLS client**: `lib/chain.resid` holds the trust store (`TrustStore`, a PEM
  bundle or a directory of DER certs) and `tls_server_trusted`, which is
  fail-closed -- no store trusts nothing, and there is no skip flag. The chain
  is walked through the intermediates in the server's Certificate message
  (`lib/tlsmsg.resid`'s `tm_cert_list`). Certificate times convert through
  `lib/calendar.resid` into an `Instant`; never reintroduce a packed civil
  integer. Fixtures for `tests/tls` are committed, so the suite needs no
  openssl and no network. `lib/tlsclient.resid` is the client half: the
  handshake, `Wire(TlsClient)`, and `tls_https_get` (one GET, Content-Length
  required, 64 MB cap, a 5 min whole-exchange deadline; `tls_https_get_within`). Traffic secrets are directional and getting them
  backwards still completes a handshake -- the client *reads* with `s_ap`
  and writes with `c_ap`. `tools/resid-fetch.resid` pulls one registry
  artifact over https and prints its SHA-256; `resid-manifest` fetches an
  `https://` registry itself.
- **Capabilities**: every function that uses a provider or effectful builtin, directly or through a callee, needs `@requires(...)` (E0219; `SECURITY.md`). Families are `filesystem`, `environment`, `args`, `process`, `network`, `terminal` and `clock`; `network`, `terminal` and `clock` carry modes like `filesystem`, so `clock(readonly)` reads the clock and `clock` also sleeps, and `network(readonly)` covers everything but `resid_tcp_listen_at` (binding a non-loopback address is the one network write, `gk_builtin_write`). A sandboxed function is emitted as a wrapper (`resid_cap_enter`, call `<name>.sb`, `resid_cap_leave`) around a TCO-able body, and the runtime counts a re-entry of the set already on top instead of pushing a frame (`cap_reps` in `runtime/rt/caps.resid`; there are 32 frames), so dependency code compiled under its ceiling loops and recurses normally. A new provider verb used by the compiler's own source needs a two-step bootstrap: build a stage from source that avoids the verb, compile the real source with it, then seed from that IR (compile with the absolute source path, as `boot.sh` does).
- **HTTP server**: `lib/httpserv.resid` (an event loop over `resid_tcp_poll`: stalled clients cost a socket, not a worker; transports are `Session(S, C)` state machines in `lib/wire.resid`/`lib/tlswire.resid`, the TLS handshake as pure steps `ts_server_start`/`ts_server_finish`; HTTP/1.1 over `List(Int)` buffers: Content-Length and chunked bodies, keep-alive, pipelining, `http_route`, `HttpLimits`, smuggling shapes refused) and `examples/http_server.resid` (worker regions sharing one listener). Streamed replies: a handler returning `HttpOut(K)` (`Whole(reply)` or `Stream(HttpStream(K))`) runs under `http_stream_loop`/`tls_stream_loop`; each `HttpStep(K)` sends bytes (chunked over 1.1, to close over 1.0) and waits `wait_ms` on the socket deadline (poll bit 4 is the tick for a drained stream, so no `clock`); `http_accept_loop` is that loop with every answer `Whole`. Bind a streaming handler to a typed closure before passing it (a bare lambda gets no type from the generic `K`). The Datastar SDK and registry web UI built on this live in the sibling `../resid-datastar` (with `../resid-json`, `../resid-serial`). Runtime sockets in `runtime/rt/net.resid`: `resid_tcp_listen` (loopback), `resid_tcp_listen_at` (any interface, a `network` write), `resid_tcp_recv_some`, `resid_tcp_shutdown`, `resid_tcp_deadline` (per-request read and reply deadlines from `HttpLimits.request_ms`/`reply_ms`, enforced in the runtime so no `clock` grant). A new TCP builtin needs four places: the `@export` in `net.resid`, the type in `typecheck.resid` and `codegen.resid`, and the `declare` in the driver tail's `hdr_core` (plus `ls_builtins` in `compiler/lsp.resid`); then reseed.
- **Native modules** (spec §47, `PLAN-native-modules.md`): `@link("m") Ret f(params) {}` (empty body) binds f to the C symbol f in LLVM IR text given with `-native m=<path.ll>` (`[native.m] path, sha256` in `resid.toml`). The family is `native_m`, mode-less. The artifact is checked and rewritten by `compiler/native.resid` (E0235-E0237: only its own symbols, intrinsics and mem*; no module asm/alias/ifunc/comdat/section/ctors; symbols renamed `native.<m>.*`), which also generates the caller stubs, the host thunks and `@resid.native.tab`. Each call runs in a fresh, seccomp-confined copy of the program (`runtime/rt/native.resid`: `resid-native-host <m>` argv, empty environment, fd 3 only, no TSC or vDSO). It is about 2 ms and stateless, and the reply is validated by the caller. Types: scalars, `Str(N)`, `Bytes(N)` (E0233). Not in `lib/`, `tools/`, `runtime/rt/` (E0232). Fixtures: `tests/conformance/native/` (`build.sh` regenerates the `.ll` from C).
- **Cryptography**: `lib/hash.resid` (`HashAlg`, SHA-384, HMAC/HKDF over SHA-256/384/512), `lib/ecdsa.resid` (P-256/P-384 ECDSA with RFC 6979 nonces, ECDH, strict DER and r‖s signatures) over `lib/p256.resid`/`lib/p384.resid` -- GENERATED by `tools/gen_nistp.py`, edit the template there (UInt(576)/UInt(832) Montgomery, complete RCB16 formulas, masked ladder), `lib/rsa.resid` (verification only, 2048-16384 bits, UInt(64) limbs, PKCS#1 v1.5 by re-encoding, PSS any salt), `lib/hpke.resid` (RFC 9180), `lib/cosesig.resid` (COSE_Sign1 all algorithms; `lib/cose.resid` stays the narrow Ed25519 form the driver imports), `lib/aesgcm.resid` (AES-128/192/256, any-IV GCM, key wrap, computed S-box). `lib/x509.resid` parses certificates strictly into `Cert` (`x509_parse`), with `SigAlg`/`PubKey`; `sig_verify` in `lib/certverify.resid` is the one dispatch every verifier uses. `lib/ec256.resid` is gone. Secret-handling code must stay branch-free: masks through `ct_hide`, `wrapping_*` arithmetic (a checked op's overflow test branches on the value), no secret 64-bit word in a `List` (values of 2^54 or more are boxed), and `ct_public` at each deliberate declassification; `tests/ct/run.sh` is the check (spec §6.8). Untrusted-input parsers must be total: a walker that steps by a length must stop on -1 or no progress (the TLS `tm_next` loop and the SAN walker both hung on truncated input).
- **Date and time**: `lib/calendar.resid` (proleptic Gregorian), `lib/duration.resid` (fixed-length spans), `lib/instant.resid` (timeline points, UTC leap seconds), `lib/zone.resid` (TZif v1/v2/v3 and POSIX TZ strings, `filesystem(readonly)` only to read the zone files), `lib/datetime.resid` (Zoned, strftime, ISO 8601 / RFC 3339) and `lib/clock.resid` (the only `@requires(clock)` surface, backed by `resid_clock_*` in `runtime/rt/time.resid`). Everything except the last needs no capability: only reading *now* is an effect.
- **Regular expressions**: `lib/regex.resid` (pure Resid, no capability): parse to an AST, compile to a Thompson NFA (`x*` as `(x+)?`, as RE2 does, so an empty pass leaves the loop), then search with a whole DFA built at compile time when it has at most 512 states (forward for the end, reverse for the start), a lazy DFA beyond that, or a Pike VM for captures and assertions. Leftmost-first, codepoint offsets, no backreferences or lookaround. `tests/regex/run.sh` checks it against Go; `bench/suite/src/st/regex-redux/resid` uses it. `toMatch` and `--filter` (`RESID_TEST_FILTER`) use `runtime/rt/regex.resid`, the same syntax as a yes/no Thompson NFA over raw memory (ASCII case folding; a pattern that does not compile matches nothing), fuzzed against Go in the same suite. `str_sb_append_slice(sb, s, a, b)` appends codepoints [a, b) of s without making the slice.
- **String escapes**: `\n \t \r \0 \\ \" \'` and `\xHH` (`kg_esc_err` in `compiler/graph.resid` refuses anything else at parse time; `\xHH` is ASCII in text, any byte in `b"..."`; NUL is refused in text). The compiler's own sources use `"\x01"`/`"\x1f"` sentinels, which decode to real control bytes now.
