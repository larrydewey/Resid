- **Status**: The compiler is self-hosted and cargo-free: `./boot.sh` links the committed seed (`build/boot/seed.ll`) and must reach a byte-identical self-compile fixed point. Its pipeline runs entirely on the knowledge graph (spec §3, `PLAN-graph-ir.md` G0–G7): parse (`compiler/graph.resid`), resolve (`resolve.resid`), check (`gcheck.resid`), reduce (`greduce.resid`), lower (`lower.resid`), and the graph artifact (`gart.resid`). The text checker, reducer, codegen and notes scan are retired. The source is read after parsing only for diagnostic text and source-map lines. `compiler/driver.resid` is generated by `tools/merge_driver.py` from `compiler/codegen.resid` (the LLVM emission layer) and `compiler/typecheck.resid` (the type algebra), followed by the hand-written driver tail. Self-hosted suites: `tests/conformance/run.sh` (204), `tests/reduce/run.sh` (14), `tests/provenance/run.sh` (20), `tests/pkg/run.sh` (17), `tests/runtime/run.sh` (10), `tests/lsp/run.sh` (13) and `tests/graph/run.sh` (436, including resid-why, resid-graph and resid-debug, live through its own ptrace backend and, when installed, gdb). The Rust pipeline and the Rust tools (`bootstrap/rust-stage0/`, `tools/resid-lsp*`, `tools/resid-notes`, `tools/resid-cache`) are deleted and in git history; the language server is `residc lsp` (`compiler/lsp.resid`). The compiler itself takes about 1.0s at a 272MB peak on the self-compile (clang's optimization and LTO link take the rest, about 13s). No `ulimit` is needed: the runtime's allocator enforces a memory budget, 4 GB for the compiler (`resid_mem_limit_set` in `compiler/driver.resid`), overridden by `RESID_MEM_LIMIT` (MB).
- **Runtime internals**: `resid_arena_*`, `resid_bulk_*`, the persist copies, `resid_internals_set` and the `resid_raw_*` primitives (PROGRESS §0zh) are compiler-only (E0220): allowed only in files under `compiler/` or `runtime/rt/` (never `lib/`), with `--runtime-internals`, which the driver accepts only for `compiler/driver.resid` or a `runtime/rt/` entry (`boot.sh` passes it).
- **Resid runtime**: the whole runtime is Resid, with no C library: programs are `-static-pie -nostdlib` binaries (plus libgcc) whose `_start` (emitted with `main`) calls `resid_start` (self-relocation, TLS); memcpy/memmove/memset, setjmp/longjmp and clone are naked assembly the compiler emits into the runtime module; malloc, threads, float text, getenv/exec and DNS are in `runtime/rt/`. `runtime/rt/*.resid` is lowered by `--runtime-module` into the committed `build/boot/rt.ll` (checked by `boot.sh`, regenerated by `--bootstrap-from-self`; commit it with the seed). Runtime code may not rely on runtime features it implements; a new compiler feature used by `runtime/rt/` needs a reseed with the old source first. When a port deletes C that stage1 needs, lower `rt.ll` first with the committed compiler (`build/boot/stage2.bin runtime/rt/rt.resid --runtime-module -o build/boot/rt`), then reseed.
- **Capabilities**: every function that uses a provider or effectful builtin, directly or through a callee, needs `@requires(...)` (E0219; `SECURITY.md`). A new provider verb used by the compiler's own source needs a two-step bootstrap: build a stage from source that avoids the verb, compile the real source with it, then seed from that IR (compile with the absolute source path, as `boot.sh` does).
