- **Status**: The compiler is self-hosted and cargo-free: `./boot.sh` links the committed seed (`build/boot/seed.ll`) and must reach a byte-identical self-compile fixed point. Its pipeline runs entirely on the knowledge graph (spec §3, `PLAN-graph-ir.md` G0–G7): parse (`compiler/graph.resid`), resolve (`resolve.resid`), check (`gcheck.resid`, with instantiation of generics and behaviors in `mono.resid`), reduce (`greduce.resid`), lower (`lower.resid`), and the graph artifact (`gart.resid`). The source is read after parsing only for diagnostic text and source-map lines. `compiler/driver.resid` is generated by `tools/merge_driver.py` from `compiler/codegen.resid` (the LLVM emission layer) and `compiler/typecheck.resid` (the type algebra), followed by the hand-written driver tail. - **Install**: `./install.sh` puts `residc` (wrapper setting `RESID_HOME`), `stage2.bin`, `rt.ll`, `lib/` and a signing key (`keys/`, kept across reinstalls) in `~/.resid` (`RESID_INSTALL` overrides); `./uninstall.sh` removes it (`--purge` also the key). The driver finds the standard library at `$RESID_HOME/lib` in an install, else `$RESID_HOME/../../lib`, and the signing key and keyring under `$RESID_HOME/keys` after `keys/`. An install goes stale on every reseed or runtime change: `boot.sh` refreshes an existing install after a successful build or `--bootstrap-from-self` (`RESID_NO_INSTALL_REFRESH=1` skips it); after any manual rebuild of `build/boot/`, run `./install.sh` again before testing through `~/.resid/bin/residc`.
- **Runtime internals**: `resid_arena_*`, `resid_bulk_*`, the persist copies, `resid_internals_set`, the `resid_raw_*` primitives (PROGRESS §0zh) and the `resid_fmt_*` text-formatting primitives of §14.1 are compiler-only (E0220): allowed only in files under `compiler/` or `runtime/rt/` (never `lib/`), with `--runtime-internals`, which the driver accepts only for `compiler/driver.resid` or a `runtime/rt/` entry (`boot.sh` passes it). A user program reaches the formatting only through an f-string hole's spec.
- **Resid runtime**: the whole runtime is Resid, with no C library: programs are `-static-pie -nostdlib` binaries (plus libgcc) whose `_start` (emitted with `main`) calls `resid_start` (self-relocation, TLS); memcpy/memmove/memset, setjmp/longjmp and clone are naked assembly the compiler emits into the runtime module; malloc, threads, float text, getenv/exec and DNS are in `runtime/rt/`. `runtime/rt/*.resid` is lowered by `--runtime-module` into the committed `build/boot/rt.ll` (checked by `boot.sh`, regenerated by `--bootstrap-from-self`; commit it with the seed). Runtime code may not rely on runtime features it implements; a new compiler feature used by `runtime/rt/` needs a reseed with the old source first. When a port deletes C that stage1 needs, lower `rt.ll` first with the committed compiler (`build/boot/stage2.bin runtime/rt/rt.resid --runtime-module -o build/boot/rt`), then reseed.

- **Registry**: `tools/resid-pkg.resid` packs, signs, publishes, serves and
  indexes; `tools/resid-manifest.resid` resolves and verifies. A registry is
  named by `[registry] path` (a directory) or `[registry] url` (an `http://` or `https://`
  base) -- not both. `resid-pkg serve <registry> [--port N] [--port-file F]
  [--cert F --key F]` is the publish side (TLS 1.3 with the cert and key,
  both refused at startup if they disagree): loopback only, GET/HEAD (PUT only with --upload), and a request
  path that could name a file outside the registry directory is refused. It
  runs on `lib/httpserv.resid` with four worker regions (`--requests N`: one).
  `resid-pkg serve --upload <keyring> --index-key <key>` takes `PUT
  /pkg/<name>-<version>.resid-pkg` signed by a keyring key (`resid-pkg
  upload <dir> <url> <keyfile> [--ca F]`), never replaces a version, and
  re-signs the index; storage goes through the `RegStore(T)` behavior
  (`DirStore` ships). `resid-pkg index list|add|remove|verify` are the publisher's non-publish
  operations; every write re-signs the whole index, and `index add` refuses a
  hash that contradicts an archive already published under that name/version.
  `url = "https://..."` goes over TLS 1.3 (`lib/tlsclient.resid`) and needs
  `[registry] ca` (a PEM bundle or a directory of DER certs; no default, so
  no store means a refusal, never a downgrade); the server side is
  `lib/tlsserver.resid`/`lib/tlswire.resid`. `tools/resid-fetch.resid`
  mirrors one artifact. `[signing] require_signatures` is
  enforced: the signed index no longer admits a package by itself.
- **TLS server**: `lib/tlsserver.resid` (the handshake, `TLS_AES_128_GCM_SHA256` and x25519 only, an alert for every refusal) with keys from `lib/tlskey.resid` (PKCS#8 or SEC1, PEM or DER, Ed25519 or ECDSA P-256/P-384) and the transport in `lib/tlswire.resid`. `lib/httpserv.resid` declares `Wire(T)` and `Accept(T, C)` and runs its connection path over them, so one handler serves both. The key file's mode is not checked: there is no stat verb. TLS secrets are typed secret (spec §48): `lib/tls.resid`'s key schedule and record layer are generic (`tlsg_*`, its `List(Int)` API the public copy), `TlsKeys` and `ServerKey` hold `List(Secret(UInt(8)))`, and ciphertext, opened plaintext and the Finished MAC leave through `TlsPublish(B)` -- so the server, client, transport and every program that runs a handshake or record (and its spawn lists) need `@requires(declassify)`.
- **TLS client**: `lib/chain.resid` holds the trust store (`TrustStore`, a PEM
  bundle or a directory of DER certs) and `tls_server_trusted`, which is
  fail-closed -- no store trusts nothing, and there is no skip flag. The chain
  is walked through the intermediates in the server's Certificate message
  (`lib/tlsmsg.resid`'s `tm_cert_list`). Certificate times convert through
  `lib/calendar.resid` into an `Instant`; never reintroduce a packed civil
  integer. Fixtures for `tests/tls` are committed, so the suite needs no
  openssl and no network. `lib/tlsclient.resid` is the client half: the
  handshake, `Wire(TlsClient)`, and `tls_https_get` (one GET, Content-Length
  required, 64 MB cap, a 5 min whole-exchange deadline; `tls_https_get_within`). Traffic secrets are directional and getting them
  backwards still completes a handshake -- the client *reads* with `s_ap`
  and writes with `c_ap` (`TlsKeys` is `r*` = what this end reads, `w*` =
  what it writes, from either side). `tools/resid-fetch.resid` pulls one registry
  artifact over https and prints its SHA-256; `resid-manifest` fetches an
  `https://` registry itself.
- **Capabilities**: every function that uses a provider or effectful builtin, directly or through a callee, needs `@requires(...)` (E0219; `SECURITY.md`). Families are `filesystem`, `environment`, `args`, `process`, `network`, `terminal`, `clock`, `device`, `display`, `declassify` and `native_<m>`; `network`, `terminal` and `clock` carry modes like `filesystem`, so `clock(readonly)` reads the clock and `clock` also sleeps, and `network(readonly)` covers everything but `resid_tcp_listen_at` (binding a non-loopback address is the one network write, `gk_builtin_write`). A sandboxed function is emitted as a wrapper (`resid_cap_enter`, call `<name>.sb`, `resid_cap_leave`) around a TCO-able body, and the runtime counts a re-entry of the set already on top instead of pushing a frame (`cap_reps` in `runtime/rt/caps.resid`; there are 32 frames), so dependency code compiled under its ceiling loops and recurses normally. Lambda bodies get the same `resid_cap_check` before each provider call (`lw_lambda`): a closure runs under the frames where it is called, not where it was made, and a spawn body that calls a closure by its bound name is charged with the lambda's needs statically (`gk_closure_facts`, E0214). A new provider verb used by the compiler's own source needs a two-step bootstrap: build a stage from source that avoids the verb, compile the real source with it, then seed from that IR (compile with the absolute source path, as `boot.sh` does).
- **HTTP server**: `lib/httpserv.resid` (an event loop over `resid_tcp_poll`: stalled clients cost a socket, not a worker; transports are `Session(S, C)` state machines in `lib/wire.resid`/`lib/tlswire.resid`, the TLS handshake as pure steps `ts_server_start`/`ts_server_finish`; HTTP/1.1 over `List(Int)` buffers: Content-Length and chunked bodies, keep-alive, pipelining, `http_route`, `HttpLimits`, smuggling shapes refused) and `examples/http_server.resid` (worker regions sharing one listener). Streamed replies: a handler returning `HttpOut(K)` (`Whole(reply)` or `Stream(HttpStream(K))`) runs under `http_stream_loop`/`tls_stream_loop`; each `HttpStep(K)` sends bytes (chunked over 1.1, to close over 1.0) and waits `wait_ms` on the socket deadline (poll bit 4 is the tick for a drained stream, so no `clock`); `http_accept_loop` is that loop with every answer `Whole`. Bind a streaming handler to a typed closure before passing it (a bare lambda gets no type from the generic `K`). The Datastar SDK and registry web UI built on this live in the sibling `../resid-datastar` (with `../resid-json`, `../resid-serial`). Runtime sockets in `runtime/rt/net.resid`: `resid_tcp_listen` (loopback), `resid_tcp_listen_at` (any interface, a `network` write), `resid_tcp_recv_some`, `resid_tcp_shutdown`, `resid_tcp_deadline` (per-request read and reply deadlines from `HttpLimits.request_ms`/`reply_ms`, enforced in the runtime so no `clock` grant). A new TCP builtin needs four places: the `@export` in `net.resid`, the type in `typecheck.resid` and `codegen.resid`, and the `declare` in the driver tail's `hdr_core` (plus `ls_builtins` in `compiler/lsp.resid`); then reseed.

The runtime names system calls by their x86-64 numbers and the compiler renumbers them (`a64_nr_table`, -1 where absent), so runtime code uses only calls both have (openat, newfstatat, mkdirat, dup3, ppoll, clone for fork; never open/stat/mkdir/dup2/poll/fork). - **Native modules** (spec §47, `PLAN-native-modules.md`): `@link("m") Ret f(params) {}` (empty body) binds f to the C symbol f in LLVM IR text given with `-native m=<path.ll>` (`[native.m] path, sha256` in `resid.toml`). The family is `native_m`, mode-less. The artifact is checked and rewritten by `compiler/native.resid` (E0235-E0237: only its own symbols, intrinsics and mem*; no module asm/alias/ifunc/comdat/section/ctors; symbols renamed `native.<m>.*`), which also generates the caller stubs, the host thunks and `@resid.native.tab`. Each call runs in a fresh, seccomp-confined copy of the program (`runtime/rt/native.resid`: `resid-native-host <m>` argv, empty environment, fd 3 only, no TSC or vDSO). It is about 2 ms and stateless, and the reply is validated by the caller. Types: scalars, `Str(N)`, `Bytes(N)` (E0233). Not in `lib/`, `tools/`, `runtime/rt/` (E0232). Fixtures: `tests/conformance/native/` (`build.sh` regenerates the `.ll` from C).

Its fault paths are tested from `tests/runtime/device_host.c` through `resid_device_host_test`, which no Resid program can name. Write-ness is read before reduction from the descriptor literal (`dv_writes`), else assumed. Device buffers are `List(UInt(8))` / `List(Secret(UInt(8)))`, never `Bytes`. Broken-descriptor tests and runs against real devices any user can open (`/dev/ptmx`, `/dev/zero`, sysfs, a DRM render node when present; `NAME.needs` skips) live in `tests/device/run.sh` (a private RESID_HOME with fixtures in its `lib/dev/`). Ioctl descriptors over `include/uapi` structs are generated, never hand-edited: `lib/dev/uapi_*.resid` (headed GENERATED) come from `tools/resid-devgen` (python3 + clang: a C probe of offsetof/sizeof/_IOWR compiled to IR for x86-64 and aarch64, values read back) over `tools/devgen/descriptors.toml` (roles, write label, secret, length links) and the committed header snapshot `tools/devgen/uapi/` (pinned in `tools/devgen/kernels.toml`); the typed wrappers (`sev_guest.resid`, `sev_guest_key.resid`, `tdx_guest.resid`, `nsm.resid`) are hand-written and use the generated `<struct>_<member>_at()/_len()`. - **Date and time**: `lib/calendar.resid` (proleptic Gregorian), `lib/duration.resid` (fixed-length spans), `lib/instant.resid` (timeline points, UTC leap seconds), `lib/zone.resid` (TZif v1/v2/v3 and POSIX TZ strings, `filesystem(readonly)` only to read the zone files), `lib/datetime.resid` (Zoned, strftime, ISO 8601 / RFC 3339) and `lib/clock.resid` (the only `@requires(clock)` surface, backed by `resid_clock_*` in `runtime/rt/time.resid`). Everything except the last needs no capability: only reading *now* is an effect.
- **Regular expressions**: `lib/regex.resid` (pure Resid, no capability): parse to an AST, compile to a Thompson NFA (`x*` as `(x+)?`, as RE2 does, so an empty pass leaves the loop), then search with a whole DFA built at compile time when it has at most 512 states (forward for the end, reverse for the start), a lazy DFA beyond that, or a Pike VM for captures and assertions. Leftmost-first, codepoint offsets, no backreferences or lookaround. `tests/regex/run.sh` checks it against Go; `bench/suite/src/st/regex-redux/resid` uses it. `toMatch` and `--filter` (`RESID_TEST_FILTER`) use `runtime/rt/regex.resid`, the same syntax as a yes/no Thompson NFA over raw memory (ASCII case folding; a pattern that does not compile matches nothing), fuzzed against Go in the same suite. `str_sb_append_slice(sb, s, a, b)` appends codepoints [a, b) of s without making the slice.
- **Reduction budgets** (spec §27, `compiler/greduce.resid`, defaults in `compiler/reduce.resid`): every budget counts work -- fuel (program steps, `--reduce-budget N|unbounded`, `[reduce] budget` in resid.toml), a top-level call's steps (65,536 doubling per retry up to fuel/8), a memory *meter* in abstract bytes (`rd_step_bytes`/`rd_call_bytes` plus value lengths; a quarter of RESID_MEM_LIMIT), depth (100,000), specs (400 per program, 8 per function: scaling them per function was measured 2026-10-09 to add 8% IR for no speed) -- and never native memory or time, so resid-ddc reproduces it. `@reduce(steps = N)` gives a function its own allowance, `@fold` requires its calls to reduce (E0903). A call with known arguments is evaluated by `gy_*` (values only, no residual; `gx_*` builds the residual at depth 0), both over the value semantics `sem_*`. Tail calls are trampolined (`gy_tramp`/`gy_hop`) and `for` loops run the same way (`gy_items_at`/`gy_range_at`): no depth, no memo entry per iteration, and only scalars and arguments are carried so they get a compacting loop region; keep it that way. Any other evaluator helper that would be a self-tail loop recurses through a second function (`gy_args_n`, `gy_tail_n`, ...): a loop's region copies the whole state, memo included, out at each exit, and a loop whose body evaluates nested calls gets a region per nesting level (1 MB page each). Graph nodes carry a kind code (`KN.kc`, `kg_kcx`: binary operators as 100 + operator, canonical Int literals as 23) for dispatch without comparing text. Running past the compiler's stack is E0902 (`resid_stack_left`, fail-closed); the allocator's budget checks resident memory before aborting, since nested regions count whole pages they barely touch. A non-default budget is the provenance record's `reduce` key.
- **String escapes**: `\n \t \r \0 \\ \" \'` and `\xHH` (`kg_esc_err` in `compiler/graph.resid` refuses anything else at parse time; `\xHH` is ASCII in text, any byte in `b"..."`; NUL is refused in text). The compiler's own sources use `"\x01"`/`"\x1f"` sentinels, which decode to real control bytes now.
