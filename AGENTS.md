## Communication
When caveman mode is active, apply wenyan-style compression: omit subjects, use verb-first order where natural in English, drop all particles/conjunctions, state cause→effect in minimal words. Output language: English.   

- **Status**: The compiler is self-hosted and cargo-free: `./boot.sh` links the committed seed (`build/boot/seed.ll`) and must reach a byte-identical self-compile fixed point. Its pipeline runs entirely on the knowledge graph (spec §3, `PLAN-graph-ir.md` G0–G7): parse (`compiler/graph.resid`), resolve (`resolve.resid`), check (`gcheck.resid`, with instantiation of generics and behaviors in `mono.resid`), reduce (`greduce.resid`), lower (`lower.resid`), and the graph artifact (`gart.resid`). The text checker, reducer, codegen and notes scan are retired. The source is read after parsing only for diagnostic text and source-map lines. `compiler/driver.resid` is generated by `tools/merge_driver.py` from `compiler/codegen.resid` (the LLVM emission layer) and `compiler/typecheck.resid` (the type algebra), followed by the hand-written driver tail. Self-hosted suites: `tests/conformance/run.sh` (341), `tests/reduce/run.sh` (19), `tests/provenance/run.sh` (56, trailer signing, trust modes, evidence against attestation, forged records under a valid signature), `tests/pkg/run.sh` (66, package integrity plus the local, remote and served registry transports, and a registry served over TLS, fetched artifact by artifact, then resolved), `tests/tls/run.sh` (130, TLS server authentication: trust store, issuer CA rules, three signature algorithms, CRL revocation, OCSP responses including delegated responders -- plus the TLS *server*: key loading, certificate/key match, pinned signatures, ClientHello parsing, and live handshakes against this repository's own client and, when installed, `openssl s_client` -- plus the TLS *client* end to end (`tests/tls/client.resid`: handshake, one request, the decrypted reply, and refusals by name and by address)), `tests/runtime/run.sh` (12, including buffered stdin and `lib/readline.resid` on a pty), `tests/http/run.sh` (2: `lib/httpserv.resid` against an in-process client, and `examples/http_server.resid` driven by concurrent python3 clients), `tests/lsp/run.sh` (18) and `tests/graph/run.sh` (627, including resid-why, resid-graph and resid-debug, live through its own ptrace backend and, when installed, gdb). The Rust pipeline and the Rust tools (`bootstrap/rust-stage0/`, `tools/resid-lsp*`, `tools/resid-notes`, `tools/resid-cache`) are deleted and in git history; the language server is `residc lsp` (`compiler/lsp.resid`). The compiler itself takes about 1.4s at a 294MB peak on the self-compile (clang's optimization and LTO link take the rest, about 13s). No `ulimit` is needed: the runtime's allocator enforces a memory budget, 4 GB for the compiler (`resid_mem_limit_set` in `compiler/driver.resid`), overridden by `RESID_MEM_LIMIT` (MB).
- **Install**: `./install.sh` puts `residc` (wrapper setting `RESID_HOME`), `stage2.bin`, `rt.ll`, `lib/` and a signing key (`keys/`, kept across reinstalls) in `~/.resid` (`RESID_INSTALL` overrides); `./uninstall.sh` removes it (`--purge` also the key). The driver finds the standard library at `$RESID_HOME/lib` in an install, else `$RESID_HOME/../../lib`, and the signing key and keyring under `$RESID_HOME/keys` after `keys/`. An install goes stale on every reseed or runtime change: `boot.sh` refreshes an existing install after a successful build or `--bootstrap-from-self` (`RESID_NO_INSTALL_REFRESH=1` skips it); after any manual rebuild of `build/boot/`, run `./install.sh` again before testing through `~/.resid/bin/residc`.
- **Runtime internals**: `resid_arena_*`, `resid_bulk_*`, the persist copies, `resid_internals_set`, the `resid_raw_*` primitives (PROGRESS §0zh) and the `resid_fmt_*` text-formatting primitives of §14.1 are compiler-only (E0220): allowed only in files under `compiler/` or `runtime/rt/` (never `lib/`), with `--runtime-internals`, which the driver accepts only for `compiler/driver.resid` or a `runtime/rt/` entry (`boot.sh` passes it). A user program reaches the formatting only through an f-string hole's spec.
- **Resid runtime**: the whole runtime is Resid, with no C library: programs are `-static-pie -nostdlib` binaries (plus libgcc) whose `_start` (emitted with `main`) calls `resid_start` (self-relocation, TLS); memcpy/memmove/memset, setjmp/longjmp and clone are naked assembly the compiler emits into the runtime module; malloc, threads, float text, getenv/exec and DNS are in `runtime/rt/`. `runtime/rt/*.resid` is lowered by `--runtime-module` into the committed `build/boot/rt.ll` (checked by `boot.sh`, regenerated by `--bootstrap-from-self`; commit it with the seed). Runtime code may not rely on runtime features it implements; a new compiler feature used by `runtime/rt/` needs a reseed with the old source first. When a port deletes C that stage1 needs, lower `rt.ll` first with the committed compiler (`build/boot/stage2.bin runtime/rt/rt.resid --runtime-module -o build/boot/rt`), then reseed.
- **Registries**: `tools/resid-pkg.resid` packs, signs, publishes, serves and
  indexes; `tools/resid-manifest.resid` resolves and verifies. A registry is
  named by `[registry] path` (a directory) or `[registry] url` (an `http://`
  base) -- not both. `resid-pkg serve <registry> [--port N] [--port-file F]`
  is the publish side: loopback only, GET/HEAD only, no upload, and a request
  path that could name a file outside the registry directory is refused. It
  runs on `lib/httpserv.resid` with four worker regions (`--requests N`: one).
  `resid-pkg index list|add|remove|verify` are the publisher's non-publish
  operations; every write re-signs the whole index, and `index add` refuses a
  hash that contradicts an archive already published under that name/version.
  `https://` is refused, never downgraded: serving one is now possible
  (`lib/tlsserver.resid`, `lib/tlswire.resid`, `examples/https_server.resid`; the client is `lib/tlsclient.resid`),
  but a client cannot fetch one: `resid build` refuses `https://` and
  `tools/resid-fetch.resid` is the way in. `[signing] require_signatures` is
  enforced: the signed index no longer admits a package by itself.
- **TLS server**: `lib/tlsserver.resid` (the handshake, `TLS_AES_128_GCM_SHA256` and x25519 only, an alert for every refusal) with keys from `lib/tlskey.resid` (PKCS#8 or SEC1, PEM or DER, Ed25519 or ECDSA P-256) and the transport in `lib/tlswire.resid`. `lib/httpserv.resid` declares `Wire(T)` and `Accept(T, C)` and runs its connection path over them, so one handler serves both. The key file's mode is not checked: there is no stat verb.
- **TLS client**: `lib/chain.resid` holds the trust store (`TrustStore`, a PEM
  bundle or a directory of DER certs) and `tls_server_trusted`, which is
  fail-closed -- no store trusts nothing, and there is no skip flag. The chain
  is walked through the intermediates in the server's Certificate message
  (`lib/tlsmsg.resid`'s `tm_cert_list`). Certificate times convert through
  `lib/calendar.resid` into an `Instant`; never reintroduce a packed civil
  integer. Fixtures for `tests/tls` are committed, so the suite needs no
  openssl and no network. `lib/tlsclient.resid` is the client half: the
  handshake, `Wire(TlsClient)`, and `tls_https_get` (one GET, Content-Length
  required, 64 MB cap, a 5 min whole-exchange deadline; `tls_https_get_within`). Traffic secrets are directional and getting them
  backwards still completes a handshake -- the client *reads* with `s_ap`
  and writes with `c_ap`. `tools/resid-fetch.resid` pulls one registry
  artifact over https and prints its SHA-256; `resid build` reaches a TLS
  registry through it (`[registry] path`), because importing
  `lib/tlsclient.resid` into `tools/resid-manifest.resid` sends the
  compiler past 20 GB in reduce (the same import in a small program is
  fine), so `url = "https://..."` stays refused there until that is fixed.
- **Capabilities**: every function that uses a provider or effectful builtin, directly or through a callee, needs `@requires(...)` (E0219; `SECURITY.md`). Families are `filesystem`, `environment`, `args`, `process`, `network`, `terminal` and `clock`; `network`, `terminal` and `clock` carry modes like `filesystem`, so `clock(readonly)` reads the clock and `clock` also sleeps, and `network(readonly)` covers everything but `resid_tcp_listen_at` (binding a non-loopback address is the one network write, `gk_builtin_write`). A new provider verb used by the compiler's own source needs a two-step bootstrap: build a stage from source that avoids the verb, compile the real source with it, then seed from that IR (compile with the absolute source path, as `boot.sh` does).
- **HTTP server**: `lib/httpserv.resid` (an event loop over `resid_tcp_poll`: stalled clients cost a socket, not a worker; transports are `Session(S, C)` state machines in `lib/wire.resid`/`lib/tlswire.resid`, the TLS handshake as pure steps `ts_server_start`/`ts_server_finish`; HTTP/1.1 over `List(Int)` buffers: Content-Length and chunked bodies, keep-alive, pipelining, `http_route`, `HttpLimits`, smuggling shapes refused) and `examples/http_server.resid` (worker regions sharing one listener). Runtime sockets in `runtime/rt/net.resid`: `resid_tcp_listen` (loopback), `resid_tcp_listen_at` (any interface, a `network` write), `resid_tcp_recv_some`, `resid_tcp_shutdown`, `resid_tcp_deadline` (per-request read and reply deadlines from `HttpLimits.request_ms`/`reply_ms`, enforced in the runtime so no `clock` grant). A new TCP builtin needs four places: the `@export` in `net.resid`, the type in `typecheck.resid` and `codegen.resid`, and the `declare` in the driver tail's `hdr_core` (plus `ls_builtins` in `compiler/lsp.resid`); then reseed. Gotcha: a top-level function named like a built-in method (`get`) is picked by method sugar (`m.get(k)`), even inside library code.
- **Date and time**: `lib/calendar.resid` (proleptic Gregorian), `lib/duration.resid` (fixed-length spans), `lib/instant.resid` (timeline points, UTC leap seconds), `lib/zone.resid` (TZif v1/v2/v3 and POSIX TZ strings, `filesystem(readonly)` only to read the zone files), `lib/datetime.resid` (Zoned, strftime, ISO 8601 / RFC 3339) and `lib/clock.resid` (the only `@requires(clock)` surface, backed by `resid_clock_*` in `runtime/rt/time.resid`). Everything except the last needs no capability: only reading *now* is an effect.
