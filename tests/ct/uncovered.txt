# Library functions that handle a secret (the surface tools/resid-ctcover.resid
# reads from the knowledge graph) and that no tests/ct case reaches, each
# with the reason. tests/ct/run.sh fails on a secret function that is in
# neither a case's reach nor this list, and on an entry here that a case
# now reaches or that no longer handles a secret. Keep it short: a
# function belongs here only when a valgrind case cannot reach it, and its
# secret work must then be reached through the functions it calls.
#
# lib/<file> <function> <reason>
lib/tlsclient.resid tls_client_connect socket I/O: the client handshake on a live connection; its secret steps (x25519g_*, tlsg_*, tls_keys_*) are cases
lib/tlsserver.resid tls_server_handshake socket I/O around ts_server_start, ts_read_prot and ts_server_finish, which tls-server-secret runs
lib/tlswire.resid tls_accept_loop socket I/O: the accept loop that runs tls_server_handshake per connection
lib/tlswire.resid tls_stream_loop socket I/O: the record loop over tls_keys_protect and tls_keys_open, which tls-record-seal-secret and tls-server-secret run
lib/tlswire.resid tls_cfg a constructor: it stores the ServerKey and computes nothing
lib/dev/device.resid dv_answer device I/O: parses the device host's reply and takes its secret outputs from the runtime (resid_device_secret); the accessors over its result (dv_out_*) are cases
lib/dev/device.resid device_engine_ioctl device I/O: the engine runs the device host; its secret outputs reach the program only through dv_answer
lib/dev/device.resid device_engine_transact device I/O: the engine runs the device host; its secret outputs reach the program only through dv_answer
lib/dev/device.resid device_engine_read_attr device I/O: the engine runs the device host; its secret outputs reach the program only through dv_answer
lib/dev/device.resid device_engine_configfs_report device I/O: the engine runs the device host; its secret outputs reach the program only through dv_answer
lib/dev/device.resid device_engine_sequence device I/O: the engine runs the device host; its secret outputs reach the program only through dv_answer
lib/dev/device_write.resid device_engine_ioctl_w device I/O: the writing engine; as device_engine_ioctl
lib/dev/device_write.resid device_engine_transact_w device I/O: the writing engine; as device_engine_transact
lib/dev/device_write.resid device_engine_configfs_report_w device I/O: the writing engine; as device_engine_configfs_report
lib/dev/device_write.resid device_engine_sequence_w device I/O: the writing engine; as device_engine_sequence
lib/dev/sev_guest_key.resid snp_get_derived_key device I/O: the SNP_GET_DERIVED_KEY ioctl; its response's secret handling is sg_key_body, which dev-sg-key-body runs
lib/dev/tpm.resid tpm_nv_read_secret device I/O: NV_Read on /dev/tpmrm0; its logic is tpm_nv_read_secret_via, which dev-tpm-nv-read-secret runs
